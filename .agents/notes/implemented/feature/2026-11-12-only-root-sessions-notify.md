# Agent Note: 只对主会话发提醒，子代理的结束不算

Status: implemented

## Problem

一次任务里，助手会派出子代理与团队成员，它们各自结束一轮。若每个结束都提醒，用户在一次任务里会收到
一屏通知；真正需要他回来的那一刻（主会话做完、报错、等他答复或审批）反而埋在里面。结果是把整个开关
关掉，连主会话的提醒也一起丢掉。

## Decision

宿主端的事件源在发布事件之前就丢掉非主会话：`origin === 'subagent'` 或 `delegationDepth > 0` 的会话
不产生通知事件。桌面弹窗投递器按同一条件再挡一次——即使某个子代理会话被点名要弹窗，也弹不出来。
浏览器端因此连这些事件都收不到，不会先弹再撤。

远程访问的权限过滤是另一条独立的门：能不能看到这条会话，由宿主的 `remoteAccess` 按调用方判断，与
「是不是主会话」无关。

## Alternatives considered

- **全部提醒**：一屏通知，用户会把整个开关关掉，等于连主会话的提醒一起丢。
- **把一批子代理合并成一条汇总**：要跟踪一批会话的结束边界、把成功与失败归并成一句话，状态复杂；
  省下的只是几条通知。
- **只在浏览器端过滤**：事件已经过 Remote 传输与权限层，每个订阅者都要为子代理会话付带宽、推进游标，
  而且「弹了再撤」比不弹更烦。

## Consequences

用户看不到子代理的结果，只能自己点开会话看。判断依据是会话头部的 `origin` 与 `delegationDepth`：
DSH 换一种表达方式时，`src/host.ts` 的 `publish()` 与 `src/index.ts` 里的 `allowsSession` 要一起改，
`test/host.spec.ts` 与 `test/desktop-host.spec.ts` 会先红。
