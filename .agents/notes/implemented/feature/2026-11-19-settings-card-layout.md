# Agent Note: 设置卡按 DSH 设置页的行节奏排布

Status: implemented

## Problem

通知配置卡原来把状态诊断文字堆成一长串灰字，加两个操作按钮，占了卡片顶部一整块；字段也各自占满整行，
和 DSH 自带设置页的排布差得远。用户看着不像原生界面，要求「布局参考 dsh 本来的自带插件设置」，同时明确
不要多余的小标题与无用信息。

第一版按这个要求改成了两列网格，勾选框靠 CSS `row-reverse` 摆到右边。实测这个写法把官方 `Checkbox`
内部的 `<span class="control">` 也选进去撑开了，勾选框落在这一行的中间而不是右边缘；同时把完整诊断挪进
`title` 属性，权限被拒时那句「请在站点设置中修改」只有鼠标悬停能看见。两点都推倒重做。

## Decision

配置卡只用官方件拼出来，不再自绘开关、状态点和按钮：

- 行就是 DSH 设置页那一行：左边一句标题（需要时下面跟一句 12px 说明），右边放它的控件，行与行之间一条
  0.5px 的 `--dsw-alias-border-l2` 分隔线，每行上下 16px。跟 `DeveloperToolsRow` 的尺寸一致。
- 勾选类字段一律用官方 `Switch`（`<button role="switch">`），不再用 `Checkbox` 加 CSS 反转：
  设置页的语义是「开/关一项能力」，开关本身就带这个语义，也不存在把内部结构一起选中的风险。
- 状态用官方 `StateDot`（`done` / `warning`），后面跟一句「已就绪 / 需要处理」，右侧仍是「允许通知」
  「测试通知」两个官方 `Button`。
- 诊断不再藏进悬停提示：只把**真的会拦住提醒**的几条逐行列在状态下面（权限未给、非安全页面、host 字段
  未就绪、桌面通道失败、激活失败、声音被拒/不可用、测试失败），没有问题时只留一行「已就绪」。首次进入时
  `audio` 是 `unknown`，不算问题，避免一进来就报警。
- 四类事件各占一行：「会话完成 / 异常中止 / 需要答复 / 需要审批」，右边依次是它的音色 `select`、
  「试听」和开关。事件与声音放在同一行，层级靠相邻表达，不再另起一行「提示音」——那一行读起来和事件
  行一样重，看不出属于谁。`select` 的可访问名字由 `aria-label` 给出（「需要答复提示音」），因为四个
  下拉都叫「提示音」；选了自定义音色时，事件下面补一行「自定义音频」（不画分隔线、标题降到 13px
  次要色），那才是事件下面的补充项。
- 八个「哪些完成要提醒」的勾选项——你发起的回合（默认勾选）、目标每轮、子代理唤醒后、后台任务
  唤醒后、团队消息唤醒后、外部事件唤醒后、插件触发后、其它来源唤醒后——放在
  「会话完成」这一行下面，做成可勾选的条目：带 `legend` 的 `fieldset`（图例「其它完成时机」），
  0.5px `--dsw-alias-border-l4` 边框、`--dsw-radius-lg` 圆角、10px 内边距；每条是整行可点的 `label`
  （原生 `checkbox` + 13px 名字，悬停高亮）。这是照 DSH 子智能体那张卡的
  `SubagentModelSelectionFields`：父开关一行，下面用带 legend 的框装「可勾选的清单」，而不是再摆
  几个开关行。每条是 13px 名字加一句 11px 说明：八项名字（「…唤醒后」）太像，说明负责说出这一项
  具体是哪个时刻；说明不写默认值，勾选状态已经表达了默认。「会话完成」关掉时整组一起收起来——父开关
  关着，这几个子选项没有任何意义。

- 音量和下拉都是原生控件（`input[type=range]`、`select`），外观照官方插件配置表单那套：0.5px
  `--dsw-alias-border-l4` 边框、`--dsw-radius-md` 圆角、32px 高。DSH 没有滑杆控件，音量保留原生滑杆。
- 保存交给官方 `SettingsForm`：只有它那个保存按钮，卡片不再自己画「放弃草稿」。唯一例外是草稿撞上别处
  的编辑（revision 变了）：官方外框只给「保存」，这时卡片补一条说明和一个「放弃草稿」，否则用户除了离开
  这一页没有别的出路。
- 不设字体、不加背景。整张卡片只取 `--dsw-*` 变量与官方控件，英文排版和同页其它设置一致。

## Alternatives considered

- **两列网格 + `Checkbox` + CSS `row-reverse`**：第一版就是它。`.field > label > span { flex: 1 }`
  把 `Checkbox` 自己的 `control` 容器也撑开了，勾选框落在行中间；改用 `:last-child` 能修，但仍然是在
  改写官方控件的内部排布，不如直接用带开关语义的 `Switch`。
- **把完整诊断塞进 `title` 悬停提示**：第一版的做法。触屏和读屏用户拿不到，而「请在站点设置中修改」
  正是他们要照做的那句话。
- **删掉状态文字和两个按钮**：最干净，但删掉「允许通知」后，浏览器没自动弹权限请求时用户无处可去，
  只能翻浏览器站点设置。
- **诊断原样保留成长段灰字**：就是用户说的「无用信息」，占空间且不像原生界面；只列会拦住提醒的几条，
  既不丢信息也不占一整块。
- **提示音单独占一行（第一版）**：四行「提示音」长得一模一样，读不出它属于上面哪个事件；把开关、
  下拉、试听并进事件行后层级自然消失，也不必再问「这一行是谁的」。—— 最初的顾虑是三个控件挤在右边会
  分不清开关管哪一项，实际排布里开关与声音之间留了 10px，且开关在最右、声音有音色名，读得出来。
- **事件与提示音分成两行，只把分隔线画在事件之间（第二版效果图）**：层级靠留白表达了，但卡片仍是
  八行，同一句「提示音」重复四次。
- **三个开关和四个事件平铺（第三版）**：它们其实是「会话完成」的子选项，平铺时读者得自己猜出这层关系；
  挪进「会话完成」下面、用 `fieldset` 圈起来，从属关系由形状直接表达。
- **父开关关掉时把这一组置灰而不是收起来**：三行点不动的控件仍然占着页面；DSH 子智能体那张卡也是
  父开关打开时才渲染模型列表，跟着它收起更省地方。
- **组里继续摆三个开关行**：组里再放开关，视觉重量和外面的开关行一样，也偏离了参考卡「可勾选清单」
  的做法；改成勾选条目后，一行一件事仍然清楚，还矮了一截。
- **沿用 `Montserrat` 品牌字体**：DSH 只在桌面引导页用它，设置页走 `--dsw-font-family`；卡片单独换
  字体反而和同页其它设置不一样。
- **shader 背景 / 打包官网字体**：前者用户看过效果图后取消；后者要么跨域要么把字体打进包，都不如直接用
  宿主自带字体。

## Consequences

卡片现在每一行只有一件事，控件贴着右边缘；窄面板（容器查询 480px 以下）把说明占满一行、控件落到下一行
的右边缘，仍在同一根中线上。实测两种宽度都对齐，四类事件的开关、下拉、试听不再互相挤压。

代价：整张卡 9 行（状态、弹窗方式、总开关、音量、四个事件），「会话完成」下面再加三个勾选项；
插件页要滚动。换来的是每一行只有一个决定，事件和它的声音不会看错，子选项也不会被当成同级事件。

官方 `Switch` / `StateDot` 在 `test/stubs/ui-primitives.tsx` 里有语义替身（`role="switch"` 与
`aria-checked`、`data-state`），`test/delivery.spec.tsx` 用可访问名字定位控件，改文案或结构时会先红；
「问题逐行列出来」和「草稿过期才给放弃入口」两条各有断言，把行为改回去测试会红。

界面改动在 `src/client/components/NotificationsSettings.tsx` 与其 CSS 模块里。提醒行为那部分决策见
[完成提醒按回合触发者过滤](../bug-fix/2026-11-19-completion-by-turn-source.md)。
