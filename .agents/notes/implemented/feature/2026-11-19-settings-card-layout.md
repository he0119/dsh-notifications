# Agent Note: 设置卡改成两列布局并保留状态入口

Status: implemented

## Problem

通知配置卡原来把状态诊断文字堆成一长串灰字，加两个操作按钮，占了卡片顶部一整块；字段也各自占满整行，
和 DSH 自带设置页的紧凑两列排布差得远。用户看着不像原生界面，要求「布局参考 dsh 本来的自带插件设置」，
同时明确不要多余的小标题与无用信息。

## Decision

配置卡的字段改成 DSH 原生设置页的两列节奏：标签在左、控件在右，每项一行，靠细分隔线分开。勾选类字段
保留官方 `Checkbox` 的可访问语义（`<label>` 包输入框与文字），用 CSS `row-reverse` 把勾选框摆到右侧。

顶部状态区保留「允许通知」「测试通知」两个操作入口和状态信息，但呈现方式改成官方那种「状态圆点 +
一句摘要 + 右侧按钮」的一行：完整诊断文字移到 `title`，摘要只说「已就绪 / 需要处理」，host 字段未就绪时
摘要直接显示那条提示。这样既不丢功能，也不再占一大块。点「测试通知」后的结果（已发送/失败等）属于操作
反馈、不是静态诊断，所以摘要优先显示它，`test/delivery.spec.tsx` 有一条断言守住这条可见反馈。

字体沿用 DSH 自带的 `Montserrat`（英文）和系统字体栈（中文），两者都随宿主提供、可离线；shader
背景经讨论后取消，卡片不加任何背景图。视觉资源都用 `--dsw-*` 主题变量，深浅主题自动适配。

## Alternatives considered

- **删掉状态文字和两个按钮**：最干净，但删掉「允许通知」后，浏览器没自动弹权限请求时用户无处可去，
  只能翻浏览器站点设置。
- **状态文字原样保留**：就是用户说的「无用信息」，占空间且不像原生界面。
- **四类事件改成单列完整字段（方案 A）或折叠分组（方案 B）**：和 DSH 自带设置的两列排布不符，用户已从
  效果图中选了两列方案。
- **shader 背景**：用户先在效果图里选了带背景，随后改变主意取消；最终不加背景。
- **下载官网字体 Host Grotesk / DM Sans**：字体文件在官网 CDN，直接引用会被跨域拦且必须联网，要离线
  就得打包字体、体积变大；DSH 自带的 Montserrat 开箱即用，够用。

## Consequences

配置卡现在紧凑、贴近原生设置，但勾选字段靠 CSS 反转实现，判断依据是 `:has(input[type='checkbox'])`；
浏览器不支持 `:has()` 时会退化成「框在左」，功能不受影响。完整诊断文字只在悬停提示里，屏幕阅读器依靠
状态点的 `role="status"` 摘要与按钮的可访问名字。界面改动在 `src/client/components/NotificationsSettings.tsx`
与其 CSS 模块里，`test/delivery.spec.tsx` 用可访问名字定位控件，改文案或结构时会先红。
