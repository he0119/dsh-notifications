# AGENTS.md — 文档规范

本目录每一份文档各有一个家；同一条信息只在一处展开，别处放链接或一句话指过去。

| 文档 | 写什么 | 不写什么 |
| --- | --- | --- |
| [development.md](development.md) | 目录结构、逐文件职责、常用命令、两个 tsconfig 的分界 | 发布步骤（→ [releasing.md](releasing.md)）；决策依据（→ [.agents/notes/](../.agents/notes/AGENTS.md)） |
| [releasing.md](releasing.md) | 本地打包试用、推标签之后工作流做什么、npm 那边要先配什么、出错怎么补救 | 安装与用法（→ [README](../README.md)）；逐文件职责（→ development.md） |
| 根 [AGENTS.md](../AGENTS.md) | 协作约定、提交信息口径、验证清单、界面与产物的硬约束 | 完整例子、逐文件职责、能从上面两份文档读到的内容 |

放一份新文档之前先问它属于哪一行；都不属于就先想清楚它是哪一类，再回来改这张表。

## 写作规则

- **只写当前状态。** 历史留在提交与决策笔记里；正文不写「原本是……后来改成……」，只点机制的名字。
- **手折行，每行 ≤ 100 字符**（中日韩字符按显示宽度算）：长链接、表格行、代码块与 YAML 头部随内容
  走，不为凑宽度硬断。
- **相对 Markdown 链接指向当下存在的文件**；历史引用用提交号或标签号。
- **数字只写实测值**：测试条数、包内文件数、量出来的字节数；机制写文件与函数名，不复述 diff。
- 中文单语。唯一的英文正文是 [README.en.md](../README.en.md)，它与 `README.md` 的键与结构保持对齐。
- 语言按根 [AGENTS.md](../AGENTS.md) 的「说人话」：写具体动作与结果，不用「收口」这类词。
- 措辞调整与纯局部实现细节不需要新的文档段落，也不需要决策笔记。

## 门禁

文档本身没有门禁。决策笔记的格式由 `test/notes.spec.ts` 核（在 `pnpm test` 里跑），本文件里那张表与
[.agents/notes/AGENTS.md](../.agents/notes/AGENTS.md) 里的分工要保持一致。
